# Domain docs

This repo uses a single-context layout. The glossary lives in `GLOSSARY.md` at the repo root. Architecture decision records (ADRs) live under `docs/adr/`.

Before exploring the codebase, read the glossary and any ADRs relevant to the area you're working on. If these files are absent, continue with the task. Use the domain-modeling skill when the work establishes a term or an architecture decision worth recording.

Use glossary terms in issue titles, proposals, hypotheses, and tests. When a term is missing, check the vocabulary already used in the repo and note a genuine gap for domain modeling.

If your proposal conflicts with an ADR, name the ADR and explain why the decision should be reopened.
